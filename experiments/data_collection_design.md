## 3.1 动捕系统上手

### 动捕是什么

光学动捕系统（OptiTrack / Vicon 等）由 8~16 台红外相机组成，环绕拍摄区域安装在天花板支架上。

**工作原理**：

```
红外相机发出 850nm 红外光
        ↓
照到 marker 球（表面是逆反射涂层，光原路弹回）
        ↓
红外相机"看到"这些亮点
        ↓
≥2 台相机同时看到一个 marker → 三角测量 → marker 的 3D 坐标
        ↓
≥4 个 marker 固定在一起、相对位置不变 → 定义为「刚体」
        ↓
系统实时输出刚体的 6DoF 位姿（位置 X,Y,Z + 朝向 四元数/旋转矩阵）
```

### 动手体验目标

- 拿一个 marker 球在动捕空间里移动，屏幕上实时看到它的 3D 位置
- 感受精度：亚毫米级（手微微动一点就能看到数值变化）
- 感受丢帧：手挡住 marker、移到相机盲区时会丢失
- 理解坐标系：动捕系统的全局坐标系原点在哪（标定时 L 形标定器放地面决定）

## 3.2 采集方案设计（回答五个核心问题）

### Q1：相机和卫星各自如何装 marker？动捕如何同时输出两者的 6DoF？

**卫星模型**：底部固定一个 3D 打印底座，上面贴 ≥ 4 个 marker 球（非对称排列，不能排成正方形/正三角形，否则系统分不清朝向）。这些 marker 球从各个拍摄角度都要能被动捕相机看到。

**相机**：热靴口或机身螺孔固定一个 3D 打印的 marker 架，同样 ≥ 4 个 marker、非对称排列。

```
卫星 marker 底座示意（俯视）：      相机 marker 架示意：

    ○           ○ ○                   ○
        ○               ○                   ○

  （不对称排列 = 系统能唯一识别朝向）


动捕系统同时跟踪这两个刚体，每帧输出：
┌─────────────────────────────────────────┐
│  相机刚体在动捕系下的位姿：T_M→RB_C(t)    │
│  卫星刚体在动捕系下的位姿：T_M→S(t)       │
│  （120Hz，两个刚体时间戳对齐）             │
└─────────────────────────────────────────┘
```

**符号说明**：

| 符号 | 含义 |
|---|---|
| M | 动捕全局坐标系（现场标定时定义，原点一般在地面某角） |
| RB_C | 相机 marker 架的刚体坐标系 |
| S | 卫星 marker 底座的刚体坐标系 |
| C | 相机光心坐标系（真正要的"相机位姿"） |
| T_A→B | 从坐标系 A 到 B 的 4×4 变换矩阵（位置 + 朝向） |

### Q2：相机内参怎么标？

用棋盘格或 ChArUco 板标定**双目相机中画质更好的那个镜头**。标一次即可，内参是相机的固定属性。

```python
# 1. 棋盘格：比如 9×6 内角点、格子边长 25mm
# 2. 手持棋盘格，从不同距离、不同倾斜角度拍 20+ 张
# 3. OpenCV 标定：

ret, K, dist, rvecs, tvecs = cv2.calibrateCamera(
    obj_points,   # 每张图棋盘格 3D 角点坐标（已知格子尺寸）
    img_points,   # 每张图检测到的 2D 角点像素坐标
    image_size,
    None, None
)
```

输出：

```
K = [[fx,  0, cx],       # 内参矩阵
     [ 0, fy, cy],
     [ 0,  0,  1]]

dist = [k1, k2, p1, p2]  # 畸变系数（径向畸变 k1,k2 + 切向畸变 p1,p2）

验证标准：平均重投影误差 < 0.5 pixel
```

**和后续环节的关系**：

- `fx` 用来算 `camera_angle_x = 2 × atan(W / (2 × fx))`，写入 `transforms_train.json`
- 生成 RGBA 之前先用 `cv2.undistort()` 去畸变
- 手眼标定的 solvePnP 步骤需要 K 和 dist 作为输入

### Q3：手眼标定——动捕刚体坐标系到相机光心坐标系的外参怎么标？

**这是整个方案最难也最关键的一步。** 动捕跟踪的是 marker 架（RB_C），我们需要的是光心（C）。两者之间有一个固定的空间偏移，手眼标定就是求解这个偏移。

#### 为什么叫"手眼标定"

类比：你的眼睛（相机光心）在头上，但你头上戴的 tracking marker（刚体）不在眼睛的位置。你要知道"眼睛相对于 marker 的确切位置"。

#### 标定流程

```
准备：ChArUco 标定板放在地上，固定不动。动捕系统已标定好。

对每一帧 i（拍 30+ 张不同角度）：
┌─────────────────────────────────────────────────────┐
│                                                      │
│  动捕侧：记录 T_M→RB_C_i                            │
│          （相机刚体在动捕系下的位姿，每帧已知）        │
│                                                      │
│  图像侧：拍一张 ChArUco 板的照片                      │
│         → 检测板子上的角点                           │
│         → cv2.solvePnP(角点3D坐标, 角点2D坐标, K, dist)│
│         → 得到 T_T→C_i                             │
│          （光心在标定板坐标系 T 下的位姿）             │
│                                                      │
│  关键：标定板不动 → T_M→T 是未知但固定的常量          │
│        marker 架不拆 → T_RB_C→C 是未知但固定的常量    │
│                                                      │
└─────────────────────────────────────────────────────┘
```

#### 数学推导

```
对于第 i 帧，光心在动捕系下的位姿有两种表达方式：

方式 1（走 marker 架）：
  T_M→C_i = T_M→RB_C_i  @  T_RB_C→C     ← 动捕输出  ↑ 待求

方式 2（走标定板）：
  T_M→C_i = T_M→T        @  T_T→C_i     ← ↑ 待求     ← solvePnP 给出

两者相等：
  T_M→RB_C_i @ T_RB_C→C = T_M→T @ T_T→C_i
```

对所有 i（i = 1..N），`T_M→T` 和 `T_RB_C→C` 是相同的未知量，联立求解。OpenCV 有现成的：

```python
# R_gripper2base, t_gripper2base：每帧动捕刚体位姿（旋转 + 平移）
# R_target2cam, t_target2cam：每帧 solvePnP 结果
# 输出 R_cam2gripper, t_cam2gripper → 拼成 T_RB_C→C

R_cam2gripper, t_cam2gripper = cv2.calibrateHandEye(
    R_gripper2base=R_gripper2base_list,   # T_M→RB_C 的旋转部分（视角转换后）
    t_gripper2base=t_gripper2base_list,   # T_M→RB_C 的平移部分
    R_target2cam=R_target2cam_list,       # T_T→C 的旋转部分
    t_target2cam=t_target2cam_list,       # T_T→C 的平移部分
    method=cv2.CALIB_HAND_EYE_TSAI        # Tsai 方法，经典稳定
)
```

**验证**：标定完用重投影误差验证——把 T_RB_C→C 代入，对每帧把标定板的 3D 角点投影到图像上，与检测到的 2D 角点比，误差 < 1 pixel 就合格。

**注意**：`T_RB_C→C` 是常量。只要 marker 架不从相机上拆下来，标一次就一直有效。

### Q4：图像帧和动捕位姿怎么做时间同步？

```
时间轴：
动捕：──●──●──●──●──●──●──●──●──→  120Hz（每 8.3ms 一帧）
相机：──────◆─────────◆─────────→  按快门时刻
              ↑                    ↑
            t_img1               t_img2

每张照片按下快门时：
  1. 记录图像时间戳 t_img（相机系统时间）
  2. 记录此刻动捕时间戳 t_mocap（动捕系统时间）
  3. 两个系统时钟不一定对齐 → 用第一帧的偏移量做对齐
     或者：相机通过网线/串口连到动捕主机，用统一时钟
```

**实操建议**：

- 手持缓慢匀速移动（给同步留余量）
- 每帧的速度 < 每秒 10cm → 8ms 同步误差 = 位置偏差 < 0.8mm，可接受
- 如果动捕 SDK 提供回调/事件机制，在每帧图像曝光信号触发时读取动捕位姿（最佳方案）

### Q5：如何把「相机位姿 + 卫星位姿」换算成卫星体坐标系下的相机 c2w？

这是把动捕输出的两坨数据变成训练所需 `transform_matrix` 的最后一步。

```
变换链（每帧 t）：

  动捕系 M ──T_M→S(t)──→ 卫星系 S（卫星 marker 底座定义的坐标系）
    │                      ↑
    │ T_M→C(t)             │ T_S→C(t) = ?
    ↓                      │
  光心系 C ───────────────┘
```

#### 计算步骤

```
已知（每帧 t）：
  T_M→RB_C(t)    ← 动捕输出：相机刚体在动捕系下
  T_M→S(t)       ← 动捕输出：卫星刚体在动捕系下

已知（标定常量）：
  T_RB_C→C       ← 手眼标定结果：光心在相机刚体系下

计算：
  Step 1: T_M→C(t) = T_M→RB_C(t) @ T_RB_C→C
          光心在动捕系下的位姿

  Step 2: T_S→C(t) = inv(T_M→S(t)) @ T_M→C(t)
          光心在卫星系下的位姿 ← 这就是 transform_matrix（c2w）
```

#### 具体数值例子

假设某时刻：

```
T_M→S = [[0.98, 0, 0.2, 1.0],     ← 卫星在动捕系下：位置 (1, 0, 0)，略旋转
         [0,    1, 0,   0],
         [-0.2, 0, 0.98, 0],
         [0,    0, 0,   1]]

T_M→C = [[0.8, 0, -0.6, 10],      ← 光心在动捕系下：位置 (10, 5, 50)，朝向卫星
         [0,   1,  0,   5],
         [0.6, 0,  0.8, 50],
         [0,   0,  0,   1]]

计算：
  inv(T_M→S) = [[0.98, 0, -0.2, -0.98],
                [0,    1,  0,    0],
                [0.2,  0,  0.98, -0.2],
                [0,    0,  0,    1]]

  T_S→C = inv(T_M→S) @ T_M→C = ...
  → 这就是写入 transforms_train.json 的 transform_matrix
```

**重要**：`T_S→C` 的"S"是卫星 marker 底座定义的坐标系，不一定等于卫星的几何前后上下。理想情况下 marker 底座设计时就让其坐标系轴对齐卫星几何轴（比如 +Z = 卫星前方）。如果对不齐，额外乘一个固定的旋转矩阵即可。

## 3.3 实际采集

### 采集前检查清单

```
□ 动捕系统已标定（Wand + 地面平面）
□ 相机内参已标定（K, dist 已知）
□ 手眼标定已完成且验证通过（重投影 < 1 px）
□ 卫星 marker 底座稳固，marker 无松动
□ 相机 marker 架稳固，marker 无松动
□ 两个刚体在动捕软件中都显示为绿色（跟踪正常）
□ 拍摄区域无遮挡（没有东西挡住 marker 到动捕相机的视线）
□ 固定光源打开，关窗拉帘，自然光不变化
□ 相机手动模式：光圈/快门/ISO/白平衡已锁定
□ 背景暗且干净（黑色吸光布覆盖）
```

### 拍摄策略（参考 Aqua 的球面覆盖）

```
水平圈（相机与卫星约同高 → 俯角 ~0°）
  绕卫星走一圈，每 10°~15° 拍一张 → ~30 帧

中高度圈（相机抬高约 30° 俯角）
  再绕一圈 → ~30 帧

高角度圈（约 60° 俯角）
  再绕一圈 → ~20 帧

补充角度（正上方、低角度仰视、侧面特写）
  → ~20 帧

─────────────────────────────────
总计 ~100 帧

每帧自动记录：
  - 图像（RAW 或最高质量 JPG）
  - 动捕位姿 T_M→RB_C 和 T_M→S
  - 时间戳
```

### 拍摄中注意

- 缓慢匀速移动，不要突然改变方向或速度（时间同步误差会被放大）
- 避免自己的身体挡住 marker（动捕丢帧）
- 不要让自己的影子落在卫星上
- 每 20 帧检查一下动捕跟踪状态，两个刚体都正常

## 3.4 后处理：转换为训练格式

### 对每帧图像做以下处理

```
输入：原始图像 + 对应时刻的 T_M→RB_C 和 T_M→S

Step 1: 时间同步
  在动捕数据流中找最近的时间戳，必要时线性插值

Step 2: 计算 c2w
  T_S→C = inv(T_M→S) @ T_M→RB_C @ T_RB_C→C
  结果是这个 4×4 矩阵就是 transform_matrix

Step 3: 坐标系检查
  确保 transform_matrix 满足 OpenGL/Blender 约定：
  相机朝 -Z 看，+Y 朝上。第 4 列前 3 行 = 相机在世界系（卫星系）中的位置

Step 4: 图像去畸变
  undistorted = cv2.undistort(原图, K, dist)

Step 5: 生成 RGBA PNG
  - RGB = 去畸变后的图像
  - A（Alpha）= 前景 mask（卫星区域 = 1，背景 = 0）
  - mask 方法：
    a) 暗背景阈值分割（黑布 + 固定光照下效果最好）
    b) SAM2 自动分割（更鲁棒，但需要 GPU）
    c) 手动抠图（最准但最慢，仅用于少量难处理帧）

Step 6: 划分 train/test
  总帧数约 100 → 隔 8 帧留 1 帧 → train 87 帧 + test 13 帧
  或者固定某些特定角度留作测试（保证测试集覆盖不同视角）

Step 7: 写 JSON
  camera_angle_x = 2 * atan(image_width / (2 * fx))
  写成 transforms_train.json 和 transforms_test.json
```

### 输出目录结构（与 Aqua 完全一致）

```
data/LabSat/
├── images/
│   ├── 0000.png          # RGBA
│   ├── 0001.png
│   └── ...
├── transforms_train.json  # 87 帧
└── transforms_test.json   # 13 帧
```

**JSON 格式示例**：

```json
{
  "camera_angle_x": 0.8727,
  "frames": [
    {
      "file_path": "images/0000",
      "transform_matrix": [
        [0.996, 0.078, 0.039, 1.736],
        [0.087, -0.889, -0.449, -16.874],
        [0.0, 0.451, -0.893, -43.0],
        [0.0, 0.0, 0.0, 1.0]
      ]
    }
  ]
}
```

## 3.6 评估与对比分析

### 定量对比

| 指标 | Aqua 仿真参考值 | 实验室实拍预期 | 说明 |
|---|---|---|---|
| PSNR | 31.53 | 预计 28~32 | 取决于位姿精度和 mask 质量 |
| SSIM | 0.984 | 预计 0.96~0.98 | 对 mask 边缘敏感 |
| LPIPS | 0.022 | 预计 0.02~0.05 | 真实纹理 vs 仿真纹理的差异 |

### 差距来源分析（按影响从大到小排列）

| 来源 | 说明 | 诊断方法 |
|---|---|---|
| **位姿误差** | 手眼标定残差 + 动捕噪声 + 时间同步抖动 | 可视化位姿球面是否有离群帧；检查动捕刚体 residual |
| **mask 质量** | 抠图不精确，边缘误把背景当前景 | 对比渲染 alpha vs 真实 mask；检查边缘渲染模糊度 |
| **光照变化** | 即使固定光源，拍摄过程中可能有轻微变化 | 检查同一位置不同时刻拍的两帧亮度是否一致 |
| **真实材质** | 卫星模型的真实材质（镀膜、多层隔热材料）比仿真更复杂 | 重点看镜面反射区域的渲染质量 |
| **运动模糊** | 手持快门不够快 | 单独检查每一帧是否清晰 |
| **坐标系偏转** | T_S→C 中卫星体系定义与卫星几何轴不完全对齐 | 对训练无影响，只影响 interpretability |

### 消融实验建议

1. **位姿精度独立性验证**：把 COLMAP 也跑一遍（仅用于对比，不是替代动捕），对比动捕位姿和 COLMAP 估计位姿之间的差异。如果差异很大（> 几度旋转或 > 几 cm），说明手眼标定可能有问题
2. **mask 消融**：先用 GT 手标 mask 训一组，再用自动分割 mask 训一组，对比指标差异
3. **渲染结果逐帧检查**：找出 PSNR 最低的那些测试帧，肉眼对比 GT 和渲染图，找原因

## 完整流程一览

```
          标定阶段（一次性）                   采集阶段
          ────────────────                 ──────────
          
    动捕系统标定                          按快门拍照
    (Wand + 地面平面)                          │
         │                             每帧记录：
    相机内参标定                         - 图像
    (棋盘格 + calibrateCamera)           - T_M→RB_C
         │                              - T_M→S
    手眼标定                             - 时间戳
    (ChArUco + calibrateHandEye)              │
         │                                    ↓
         ▼                              后处理脚本
    所有常量确定：                    ┌──────┴──────┐
    - K, dist                        │ 时间同步      │
    - T_RB_C→C                       │ 计算 T_S→C   │
                                     │ 去畸变 + mask │
                                     │ 写 JSON       │
                                     └──────┬──────┘
                                            ↓
                                     data/LabSat/
                                     (与 Aqua 格式一致)
                                            ↓
                                     2DGS 训练 + 评估
```
